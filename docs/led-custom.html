Welcome to the LED Banner Custom Pattern Creator.

The Code Lab within the app allows you to programmatically generate complex static patterns and high-performance, multi-frame animations using pure JavaScript. This guide covers everything from basic syntax to advanced mathematical rendering techniques.

1. How the engine works (the pixel shader model)

Unlike traditional canvas drawing where you explicitly draw lines or circles, the LED Banner app uses a pixel shader model.

When you click "RUN CODE", the engine evaluates your JavaScript function once for every single LED (pixel) on the grid, and it does this for every single frame of your animation.

Your code is inside a loop that looks conceptually like this:

for (let f = 0; f < requestedFrames; f++) {
  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      // YOUR CODE RUNS HERE
      // You must return what this specific LED should do.
    }
  }
}

2. API & environment variables

Inside your code, you have immediate access to a rich set of environment variables and APIs to control the exact state of the LED grid.

Grid & position variables

  • r (Number) — the current row index (starts at 0, goes down).
  • c (Number) — the current column index (starts at 0, goes right).
  • rows (Number) — total number of rows in the grid.
  • cols (Number) — total number of columns in the grid.

Animation variables

  • f (Number) — the current frame index being generated (defaults to 0 for a static pattern).
  • frames (Number) — the total number of frames requested by the animation.

The api object (animation controls)

By default, the engine evaluates a single static frame. If you want to generate a multi-frame animation, you must use the api object.

  • api.setFrames(number) — tells the engine how many frames to generate. Example: api.setFrames(24);
  • api.setFps(number) — sets the playback speed in frames per second. Example: api.setFps(15);
  • api.setLoop(boolean) — controls whether the animation loops. Example: api.setLoop(true);

Note: call these API functions at the very top of your code, outside of any if statements.

3. Output formats (return types)

Your code must return a value. This value dictates the state of the current LED at position (r, c) on frame f.

A. Boolean (simple on/off)

Return true to turn the LED ON (using the default color selected in the UI), or false to turn it OFF.

// Draws a diagonal line across the grid
if (r === c) {
  return true;
}
return false;

B. Object (precise color control)

For advanced effects, return an object to define exact hex colors or valid CSS colors.

// Draws a checkerboard pattern with custom colors
if ((r + c) % 2 === 0) {
  return { on: true, color: "#FF00FF" }; // Neon Pink
}
return { on: true, color: "#00FFFF" };   // Cyan

4. Professional recipes & examples

Copy and paste these directly into the Code Lab to see them in action.

Example 1 — The sweeping rainbow (animated)

This creates a rainbow wave that shifts horizontally across the screen, using HSL colors for smooth hue transitions.

api.setFrames(30);
api.setFps(20);
api.setLoop(true);

// Calculate hue based on column position and the current frame
let hue = ((c / cols) * 360) + ((f / frames) * 360);

// Return an HSL string (the engine automatically normalizes this to hex)
return { on: true, color: `hsl(${hue}, 100%, 50%)` };

Example 2 — Bouncing DVD logo / ping pong (animated)

A solid block that bounces around the edges of the grid.

api.setFrames(60);
api.setFps(30);

// Calculate X and Y bouncing using a triangle wave (absolute sine representation)
// Math.abs( (frame % (length * 2)) - length ) gives a perfect ping-pong bounce
let xCycle = cols - 1;
let yCycle = rows - 1;

let currentC = Math.abs((f % (xCycle * 2)) - xCycle);
let currentR = Math.abs(((f * 1.5) % (yCycle * 2)) - yCycle); // 1.5x speed on Y axis

// Draw a 2x2 block
if (Math.abs(r - currentR) <= 1 && Math.abs(c - currentC) <= 1) {
  return { on: true, color: "#FFDD00" };
}

return false;

Example 3 — Rotating radar sweep (animated trigonometry)

This draws a sweep scanner with a trailing fade using polar coordinates and angular distance.

api.setFrames(60);
api.setFps(25);
api.setLoop(true);

let cx = (cols - 1) / 2;
let cy = (rows - 1) / 2;
let dx = c - cx;
let dy = r - cy;

let dist = Math.sqrt(dx * dx + dy * dy);
let angle = Math.atan2(dy, dx);

// Current sweep angle (-PI to PI)
let sweepAngle = (f / frames) * Math.PI * 2 - Math.PI;

// Angular distance from the sweep line
let diff = Math.abs(angle - sweepAngle);
if (diff > Math.PI) diff = Math.PI * 2 - diff;

// Brightness based on proximity to the sweep line
let brightness = Math.max(0, 1 - diff * 3.5);

return {
  on: brightness > 0.1,
  color: `hsl(120, 100%, ${30 + brightness * 50}%)` // Classic green radar
};

Example 4 — Pulsing neon heartbeat (animated pulse)

Uses a central sine wave to create a pulsing/breathing neon glow effect at the core of the grid.

api.setFrames(30);
api.setFps(15);
api.setLoop(true);

let cx = (cols - 1) / 2;
let cy = (rows - 1) / 2;
let dx = c - cx;
let dy = r - cy;
let dist = Math.sqrt(dx * dx + dy * dy);

// Breathing pulse size over time (value between 0 and 1)
let pulse = Math.sin((f / frames) * Math.PI * 2) * 0.5 + 0.5;
let maxRadius = Math.min(cols, rows) * 0.4 * (0.6 + pulse * 0.4);

// Active if inside the breathing radius
let active = dist <= maxRadius;

// Shifting color lightness based on pulse intensity
let lightness = 30 + pulse * 45;

return {
  on: active,
  color: `hsl(180, 100%, ${lightness}%)` // Bright neon cyan
};

5. Under the hood & best practices

  1. High-performance SQLite storage: custom patterns are stored in a dedicated SQLite database, backed by thread-safe connection pooling. This lets you store patterns with massive frame counts (e.g. 90–120 frames at 30 FPS) without running into AsyncStorage size limits or slow loads.
  2. GPU optimization via color quantization: to avoid hundreds of draw calls for complex gradients (like HSL waves), the engine quantizes dynamic colors into 32-step RGB buckets, grouping similar-shade pixels into a single Skia path builder. This cuts total GPU draw calls from hundreds to under ~15 with no visible quality loss on the pixelated LED board.
  3. Direct static rendering: custom patterns bypass Reanimated UI-thread worklets and draw natively in Skia using static paths, achieving smooth 60 FPS playback on all iOS and Android devices.
  4. "Off" vs "black": returning false turns the LED physically off (unpowered). Returning { on: true, color: "#000000" } keeps it on, emitting black — it looks the same but stays powered in the data. Use false when you mean empty space.
  5. Code editor tools: use the CLEAR button in the Code Lab modal to immediately wipe the text area and start fresh when editing code.
